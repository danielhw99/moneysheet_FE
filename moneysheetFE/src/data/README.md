# 데이터 접근 경계 — 이슈 #13

- `models.ts`: 원본 데이터·입력 타입. 예산 원본에는 UI 잠금이나 지급 합계를 저장하지 않습니다.
- `MoneySheetDataAccess.ts`: Promise 기반 조회·저장 계약, 읽기 전용 요약 타입, 오류 코드. 실제 HTTP 경로·DTO·인증 계약이 아닙니다.
- `DataProvider.tsx`: 하나의 구현 인스턴스 선택. 현재 mock이며 이후 HTTP 구현을 주입할 수 있습니다. 저장 중 중복 요청을 막고 성공 시 조회 버전을 갱신합니다.
- `useDataQuery.ts`: 화면·날짜·월·조회 버전별 비동기 상태, 로딩·오류·재시도 처리. 이전 요청은 해제된 effect와 키 검사를 통해 현재 화면을 덮어쓰지 못합니다. 같은 조회의 재로딩 실패는 마지막 데이터와 편집 draft를 보존합니다.
- `validation.ts`: 입력 단계 날짜·금액 검증. mock 저장 경계도 동일한 검증을 적용하며, 실제 BE 연결 후에도 서버 검증을 대체하지 않습니다.
- `values.ts`: 금액의 입출금 표시 부호 변환. 합계·업무 계산은 mock 조회 구현에서 담당합니다.
- `mock/fixtures.ts`: 초기 예산·기록·카테고리·프로필·홈 달력 시연 값.
- `mock/rules.ts`: 식비·메모 상태 등 mock 업무 규칙.
- `mock/queries.ts`: Daily·Monthly·예산/식비 회차·기록 요약 계산.
- `mock/createMockDataAccess.ts`: 인스턴스별 메모리 저장소. 호출자가 원본을 우회 변경하지 않도록 입력·출력을 복사하며, 오류는 DataAccessError로 reject합니다.

화면과 App은 mock을 직접 import하지 않습니다. App에는 화면·날짜·예산 잠금만 남고, 업무 데이터의 원본 소유자는 provider가 선택한 구현 하나입니다. 동기 호환 파일 `moneyRecords.ts`와 `features/budget/budget.ts`는 제거했습니다.

편집 중 입력·탭·날짜·UI 잠금·비교 잔액은 FE 상태입니다. 저장·삭제 실패 시 폼은 닫지 않으며 입력을 유지합니다. 현재는 단일 사용자 프로토타입이며 실제 인증·사용자 전환은 구현하지 않았습니다.

구현 범위와 남은 제약:
- 홈은 저장된 내역·고정지출 지급·활성/완료 메모와 날짜별 여유비를 조회합니다. 현재 월은 오늘까지, 지난 월은 월말까지의 여유비를 월 요약에 사용하며 미래 월의 여유비 요약은 0원입니다. 미래 날짜는 입력된 Daily 기록이 있을 때만 달력 정보를 표시합니다.
- 식비는 updateFoodBudget으로 주중·토·일 값을 월 단위로 저장합니다. 현재 월 전체에 소급 적용하고 지난달 변경은 저장 경계에서도 거부합니다.
- 프로필은 시연 값이며 회원가입·로그인·프로필 수정은 실제 인증·저장과 연결하지 않았습니다.
- 은행 비교 잔액은 빈 값으로 시작하며 미입력과 0원을 구분합니다. FE 입력용으로만 사용하고 업무 계산에 포함하지 않습니다.
- 영속 저장·은행 연동·서버 권한 검사는 구현하지 않았습니다. 새로고침하면 데이터가 초기화됩니다.
- 개발용 계정 자동 입력은 기존 UI 도우미이며 인증 응답이나 사용자 데이터로 취급하지 않습니다.

실제 API 연결 시에는 HTTP 구현이 같은 인터페이스를 구현하고, 최종 계산·검증은 BE Service가 담당합니다. 현재 mock 메서드는 즉시 완료되는 Promise이므로 네트워크 지연·실패 상태의 실환경 검증은 별도로 필요합니다.

## 이슈 #15 2차 계산·표시 기준
- 오늘 여유비 = 전날 마감 여유비 + 오늘 식비 - 오늘 본인 지출. 월 1일의 기초값은 해당 월 고정여유비입니다.
- 남은 회차 식비 = 현재 회차 예산 - 회차 시작일~오늘의 식비 예산 합계. 회차 마지막 날은 0원입니다.
- Main = 오늘 여유비 + 남은 회차 식비 + 해당 월 누적 일반 입금 + 활성 메모 합계. 식비 절약분은 당일에 반영되고 다음 날 중복 가산하지 않습니다.
- 홈 총지출은 Monthly와 같은 예산 기준 총지출입니다. Daily 본인 지출 합계와 별도 개념입니다.
- 달력은 내역(지출·입금), 고정지출 지급, 메모, 여유비 순서로 각 항목을 표시합니다. 내역 파랑·고정 빨강·메모 검정·여유 초록 점 뒤에 금액 또는 건수를 표시하고, 큰 값은 줄바꿈하여 보존합니다. 항목 이름은 날짜 버튼의 접근 가능한 설명에 유지합니다. 상세 내용은 날짜를 눌러 Daily에서 확인합니다.
- 식비 변경은 저장 성공 후 계산에 반영합니다. 실패 시 입력을 유지하고 잠그지 않습니다. 상단 잠금 토글은 입력을 보존한 채 편집만 제한합니다. 미저장 변경이 있으면 안내하며 실제 저장은 하단 저장 버튼에서 수행합니다.
- 매월 1일 Daily 고정지출 영역의 고정여유비 자동 지급 표시는 allowancePayment 조회값입니다. 수동 지급 기록을 생성하지 않으며 잔액 계산에 추가 합산하지 않습니다. 해당 월 고정여유비가 삭제되면 표시하지 않습니다.
