# 데이터 접근 경계 — 이슈 #13 1차

- `models.ts`: 원본 데이터·입력 타입. `MonthBudget`와 `FixedBudgetItem`은 기존 동기 화면 호환 타입이며 `locked`·`paid`는 새 저장소 원본에 저장하지 않습니다.
- `MoneySheetDataAccess.ts`: Promise 기반 조회·저장 계약과 읽기 전용 요약 타입, 오류 코드. 실제 HTTP 경로·DTO·인증 계약이 아닙니다.
- `mock/fixtures.ts`: 기존 예산·기록·카테고리·프로필·홈 달력 시연 데이터. 비교 잔액은 FE 입력 예시이며 업무 계산 대상이 아닙니다.
- `mock/rules.ts`: 기존 업무 계산·입력 검증. 식비 기본값은 한 곳에서 공유합니다.
- `mock/queries.ts`: Daily·Monthly·예산/식비 회차·기록 요약. 원본과 별도로 수정할 수 없는 조회 결과입니다.
- `mock/createMockDataAccess.ts`: 인스턴스별 메모리 저장소. 결과와 입력을 복사해 호출자가 원본을 우회 변경하지 못하게 합니다. 오류는 `DataAccessError`로 reject합니다.

1차에서는 `moneyRecords.ts`와 `features/budget/budget.ts`의 호환 export를 통해 기존 동기 화면을 유지합니다. App의 기존 React 상태·저장 동작과 화면의 계산 호출은 2차 연결 때 교체합니다. 새 mock 저장소를 현재 App과 함께 별도로 실행하지 않습니다.

2차 목표: 하나의 데이터 접근 인스턴스를 선택하고 화면을 Promise 조회·저장 결과에 연결합니다. 편집 draft·탭·선택 날짜·UI 잠금은 FE 상태로 유지합니다. 추후 HTTP 구현은 동일한 인터페이스를 구현하되 최종 계산·검증은 BE Service가 담당합니다.

의도적으로 유지한 미구현 범위:
- 홈 요약은 `demo-snapshot`이며 실제 기록과 연결하지 않았습니다.
- 식비 설정은 조회 경계만 준비했습니다. 저장 기능은 별도 기능 작업입니다.
- 프로필은 시연 값이며 회원가입·로그인·프로필 수정은 실제 인증·저장과 연결하지 않았습니다.
- 영속 저장·은행 연동·서버 권한 검사는 구현하지 않았습니다.
- 개발용 계정 자동 입력은 기존 UI 도우미이며 인증 응답이나 사용자 데이터로 취급하지 않습니다.
